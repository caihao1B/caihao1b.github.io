## 2. 浏览器实际检查

### 机械臂

- `pick_contact` 预设显示 J2=1.20、J3=1.17、J5=−0.30 rad，末端坐标约为 `(0.353, 0.000, 0.080) m`。
- 播放后时间推进，暂停后进入暂停状态；可以切换关节坐标轴。
- 跳转“03 附着与携带”后，时间、源预设角度和附着服务意图说明同步更新。
- 窄屏显示为上下分栏。调整宽度小于 500 px 的投影，避免 home 姿态与顶部说明重叠；移动窄屏状态徽标，使其位于说明文字下方。

### 论文、录像和场景

- 选择 D2 后，说明面板切换到剩余几何重建及其适用条件。
- 录像章节跳转至 180 秒；浏览器报告总时长约 383.8 秒、媒体 readyState=4、无解码错误。

### 布局

桌面检查了主视觉、机械臂和交互面板。窄屏检查使用 390 px 宽 iframe，内容区约 375 CSS px；检查时 `body.clientWidth` 与 `body.scrollWidth` 同为 375，没有整页横向溢出。顶部章节导航允许横向滚动，这是为了保留可触达的章节入口。

浏览器日志检查中未发现当前页面应用错误；存在浏览器扩展自身的无关日志。该检查不能代替所有浏览器版本或真实手机的兼容性验证。

## 3. 数学验证的含义

正运动学比较确认：网页按源 Xacro 的关节原点、旋转轴和角度计算 `base_footprint → grasping_frame`，与独立矩阵实现一致。它不证明轨迹可由源控制器完整执行，不验证碰撞、力学、抓取接触或任务成功。

网页已披露源配置的两处差异：夹爪 open=0.20 m 超过 URDF 0.06 m 上限；部分关节预设超过 Gazebo position 接口的 −1…1 范围。前端只对夹爪可视几何限幅，没有修改用户 ROS 源工程，也没有声称修复控制器。

## 4. 运行与证据边界

- 本次没有启动 ROS 2 / Gazebo，没有连接真实机器人，没有录制新的机器人执行视频。
- 浏览器预览经本地 HTTP 加载。直接双击打开的设计使用本地经典脚本和打包资源，不依赖 fetch、模块导入、CDN 或外部接口；本次没有在浏览器工具中测试 file:// 协议。
- 没有对导出 PNG、每个速度档位、所有视角与任意关节组合做穷举测试。
- 论文图表和统计来自已提交论文；本次只核对、提取和展示，没有重新生成实验结果。
- 页面录像是用户原录像的完整时序压缩版。它保留末段导航看门狗停止及任务失败，不视为完整任务成功证据。
- 网站中的附着提示表示源码服务调用意图，浏览器没有获取真实 Attach/Detach 服务回执。
