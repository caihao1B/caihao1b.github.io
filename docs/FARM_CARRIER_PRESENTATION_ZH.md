# 项目展示说明：母车与农田机器人协同调度

## 1. 这页展示什么

展示对象是本次已经完成的独立 Java 仿真工程。母车负责运输和田边服务，三台机器人负责田内条带作业。系统可以按顺序完成运输、卸载、分配条带、作业、资源返航、排队补给、断点续作、回收装车和返回基地。来源工程提供了地图与业务背景；网站介绍的是当前可运行版本的完成内容。

建议对外项目名称：**母车与农田机器人协同调度系统——基于 Agent 与有限状态机的全流程仿真**。网站的“行为树”用于讲解调度结构，名称中不宜直接写成“已实现行为树执行引擎”。

## 2. 一个三到五分钟的展示顺序

### 第一步：用一句话说明问题（约 30 秒）

“单台机器人会走并不足以完成整场作业；还要决定由谁运送、什么时候释放、谁领取哪条任务、资源何时耗尽、如何返回补给，以及所有机器人什么时候可以一起撤场。”

在地图上指出源田块、入口、母车集结点、近田基地和道路。田块约 12.39 公顷，保留 Feld 13 的源边界；近田基地和道路为演示配置。不要将这条短道路说成已采集的真实农场运输路线。

### 第二步：解释 Agent 与状态机（约 45 秒）

播放标准场景，到机器人开始工作后暂停。选中 `robot_1`，让观众同时看到位置、任务、资源与执行状态。Agent 是保存这些数据并执行行为的实体，有限状态机约束它当前可以做什么。机器人可以同时具有“有任务、需要补料、尚未回到母车”等属性，但当前执行状态只能是 `RETURNING` 等某个具体阶段。

切换状态机视图，说明母车与机器人有各自的状态。母车从运输进入部署、服务作业和回收；机器人从车上进入卸载、入田、作业、返航、排队、补给与装车。共享资源不是复制到每台机器人身上的独立工位。

### 第三步：展开整体调度与资源循环（约 60 秒）

展示完整调度树，再进入某台机器人对应的分支。先解释任务级判断：是否故障锁定、是否仍在运输或部署、是否有未完成条带、是否需要回收，以及全员是否确实装车。再解释 Agent 级判断：是否有任务、能量够不够往返、材料是否够用、货箱是否将满、入口和补给工位是否可用。

点击节点查看对应条件、动作和源码映射。强调树是对实际 Java 规则与状态机的解释视图，节点高亮依据运行记录；当前工程没有 BehaviorTree.CPP 的节点执行和返回状态记录。

### 第四步：用补给证明不是一段预设路线（约 60 秒）

跳到某台机器人返航或服务时刻。返航触发会考虑沿合法路线返回母车的距离、移动功率和安全余量；物料不足或货箱将满也可以触发返回。入口通道、装卸坡道和补给工位分别容量为 1，补给采用队列。机器人保存条带所有权和已完成米数，补给后从断点继续。

标准场景的完整流程为约 82.06 分钟仿真时间，9 个已完成服务周期；最终母车回到基地，3 台机器人都在车上。计划条带完成度为 100%，这个指标不等于已证明真实机具无漏覆盖。

### 第五步：展示异常与工程边界（约 45 秒）

切换阻路或设备故障场景，查看 `WAITING_RECOVERY`。故障和道路锁相互独立，清除道路不等于维修了机器人。该状态冻结整个仿真时钟；演示中的恢复来自明确的脚本操作命令。记录包含等待阶段，但不能用这段仿真时长评价现实维修停机损失。

最后指向原项目下载和验证记录。可以进一步讨论如何接入真实定位、导航、充电、装卸反馈，以及如何用 CCPP 模块替换当前简化的田内路线。

## 3. 与另外两个项目如何形成一个完整叙事

| 模块 | 负责的问题 | 当前证据与接口 |
|---|---|---|
| 全覆盖路径规划 | 田块怎样分解、按什么顺序访问、车辆怎样转弯 | 原 CCPP 页面展示算法、网格、曲线与数值验证 |
| 本项目任务调度 | 哪台机器人执行、何时补给、怎样续作、何时回收 | Java 核心、配置地图、状态与事件、资源守恒及全过程验收 |
| ROS 2 在线执行 | 将计划交给机器人，接收动作结果与现场反馈 | 项目概述单独说明；本项目附冻结计划适配器，但尚未完成与 Java 调度的实时反馈闭环 |

这三个模块适合逐步结合。首先统一坐标、机器人 ID、任务 ID 与计划段；其次接入 `NavigateToPose` / `FollowPath` 等执行反馈；再把真实部署、服务和装车完成信号写回任务层。当前网站不将这条未来集成路线标为已经实机运行。

## 5. 能力边界与后续实现

- 田内机器人是二维质点，未建模转弯半径、车体包络、坡度、土壤和速度跟踪。
- 三个容量为 1 的资源实现逻辑互斥，但田内任意交叉路径没有连续时间避碰保证。
- 默认幅宽、功率、电池和容量参数是演示输入，需要按真实机具标定。
- 静态几何计划与运行时动态分配不同；网页采用运行快照和真实条带所有者，避免把名义导出计划冒充完整调度过程。
- 非空障碍物当前会被拒绝；没有默默忽略障碍，也没有把这个限制包装为已实现的障碍规划能力。
- AnyLogic 适配接口与 ROS 2 冻结计划执行器是集成基础，厂商运行时、Gazebo 全链路和机械装卸机构尚未端到端实测。
